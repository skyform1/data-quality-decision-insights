# Data Quality and Decision Insights

Analytical application for dataset validation, data-quality findings and evidence-linked review actions.

Independent portfolio work developed through problem framing, product design, full-stack implementation and evaluation, with AI-assisted development. The application connects a CSV/XLSX upload to transparent checks, persisted analysis history and an executive report. Uses original synthetic examples and deterministic rules; no live AI or trained model is connected.

## View the example

Open DEMO.html. It is a static report generated by the Python engine from sample_data/service_requests.csv: 33 fictional service requests with deliberately introduced missing fields, duplicate records, delayed/failed statuses and SLA flags. The full application supports uploads when run locally; the standalone report does not.

## What works

- CSV/XLSX upload and preview, with file and dataset size limits.
- Completeness, full-row duplicate, identifier duplicate, possible zero-value and numeric outlier checks.
- Explicit SLA-breach and status flags, with counts and affected columns.
- Header-based context hints; tied or unmatched context remains generic.
- Proposed actions ranked by finding severity and affected-record count.
- FastAPI backend, React/TypeScript frontend, saved local analysis history and Markdown report export.
- Optional shared API key for all data read/write routes. Local use without a key is a development convenience, not an authentication claim.

## Run locally

Requires Python 3.10 or later and Node.js 22 or later. Open a Terminal in the extracted folder.

```sh
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r backend/requirements.txt
python3 -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

In a second Terminal:

```sh
cd frontend
npm ci
npm run dev
```

Open http://127.0.0.1:5173. Select sample_data/service_requests.csv from the project root and run the analysis. Reopen its saved result from Local History and download its report. Optional DATA_INSIGHTS_API_KEY is configured in the backend environment and entered into the local UI for the session; it is not stored or baked into the client bundle. Never commit a real key.

VITE_API_URL can explicitly override the local backend address before launching the frontend. Default data processing is local, with no remote database, model provider or telemetry.

## Method and interpretation

The quality index is a narrow completeness/uniqueness heuristic:

`round(100 × (1 − missing cells / total cells) × (1 − duplicate rows / total rows))`

It does not include every finding and does not certify overall quality. A dataset can score highly while containing consequential SLA issues, conflicting identifiers or misleading values. The high-severity count reports the number of high/critical findings, not a probability of harm. Finding severities follow illustrative affected-ratio thresholds: 20% critical, 10% high, 5% medium, otherwise low.

ID checks apply to explicitly named ID-like columns. Numeric zero and outlier checks are screening rules; zero values and outliers may be legitimate. SLA interpretation requires an explicit sla_breached field using true/false or 1/0. Status flags are descriptive, not causal evidence. Findings can overlap, and displayed result lists are capped. See docs/METHOD.md.

## Boundaries

No schema discovery guarantees, entity resolution, causal inference, automatic correction, live AI, independent model evaluation, validated business benefit or production deployment is claimed. Recommendations require human review. No calibrated confidence or invented ROI is reported.

The sample is industry agnostic. Replace it only with fictional or appropriately authorised data. Runtime files persist on the local machine in backend/runtime; remove them when no longer needed. No multi-user isolation, login, audit ledger, encrypted storage or hardened parser sandbox is included. Serve on loopback only; this is not a secure external sharing service.
